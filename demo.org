#+Title: Org mode Basic Information

* Headings and sections

Headings start with ~*~ and the number of starts define the heading level.
A couple of ~**~ create the second level. And so on...

Instead of typing many ~*~s, can use TAB at the beginning of the line and de-indented with Shift-TAB.

The text under the heading becomes the section text and is indented according to the parent heading.

Note: The confusion: coming from markdown, I thought that ~*~ starts a list.
But this is not a list, this is a heading (similar to markdown's ~#~, ~##~, etc.
It is displayed in org mode as a hierarchical (and collapsible) structure, so it kind of looks and works like a list too.

* Controlling and navigating the document structure

Use ~TAB~ on when cursor is on the document node (in insert mode in evil) to collapse/expand the current node (cycles through states)
+ The cycle is: Folded -> Children -> Subtree

Use ~Shift-TAB~ to collapse/expand all nodes
+ The cycle is: Overview -> Contents -> Show all

~TAB~ / ~Shift-TAB~ are multi-functional, effect depends on the context:
+ After the heading marker (~*~) it shifts / unshifts the marker.
+ On the table, it formats the table
+ On the list item (heading) it cycles through folding states.
+ More commands to control the visibility: [[info:org#Global and local cycling][org#Global and local cycling]]

Note: The ~M-x toggle-truncate-lines~ is useful to toggle truncation on and off.

Motion commands:
+ Next heading: C-c C-n (org-next-visible-heading).
+ Previous heading: C-c C-p (org-previous-visible-heading).
+ Next heading same level: C-c C-f (org-backward-heading-same-level).
+ Previous heading same level: C-c C-b (outline-backward-same-level).
+ Backward to higher level heading: C-c C-u (outline-up-heading).

Structure editing commands:
+ Insert new heading on the same level: M-RET (org-meta-return)
+ Insert new TODO heading on the same level: M-S-RET (org-insert-todo-heading)
+ Cycle through levels in a new empty entry: TAB (org-cycle)
+ Promote/demote heading or list item: M-LEFT (org-metaleft), M-RIGHT (org-metaright)
+ Move subtree up or down: M-UP (org-move-subtree-up), M-DOWN (org-move-subtree-down)
+ [[info:org#Refile and Copy][Refile]] entry or region to a different location: C-c C-w (org-refile)
+ Narrow/widen buffer to current subtree: C-x n s (org-narrow-to-subtree), C-x n w (widen)

Filtering the document ("sparse tree"): we can filter the document (collapse unreleated headings) based on several properties (such as TODO items, tags, dates). The simplest mode is "Regex" where we can enter the search team and only keep sections that contain it expanded.

Sparse tree commands:
+ Prompt for the filter type: C-c / (org-sparse-tree)
+ Occur: prompts for a regexp: C-c / r (org-occur)
  + Higlights occurrences, highlight can be removed with C-c C-c.

* Lists

Lists can be started with ~+~, ~-~ or ~*~ (the ~*~ should not be after the new line or it will be a heading), the list with ~+~ markers:
+ Item 1
  + Item 1.1
    + Item 1.1.1 (use TAB to indent sub-items)
+ Item 2
  + Item 2.2 (items can also be indented by adding more spaces before the marker)

Structure editing commands (see above) that can be used for headings also useful for lists.
So, for example, ~M-Up~ / ~M-Down~ move list items up and down.

List with ~-~ marker and check-boxes (added with ~[ ]~, ~[x]~, ~[-]~)
- [ ] not started
- [-] in progress
- [X] complete

** TODO Use ~TODO~ to mark the heading as a task and add tags      :tag-one:tag-two:

The ~[/]~ and ~[%]~ add "cookies" that display task progress as "N/M" and "X%".

To toggle the todo state (unmarked -> TODO -> DONE): ~M-x org-todo~ (C-c C-t).
Or just edit it ("TODO" -> "DONE").

It is [[info:org#Workflow states][possible]] to have more states than TODO and DONE.

And more features: add note/timestamp when changing states, set priorities, subtasks, checkboxes.

Scheduling:
+ SCHEDULED: <2021-01-01> - Schedule an item for a specific date.

Use ~M-x org-toggle-checkbox~ to toggle the current checkbox and recalculate cookies.
Use ~M-x org-toggle-radio-button~ to toggle the current checkbox as radio-button (untoggle the rest on the same level).

More commands: [[info:org#Checkboxes][org#Checkboxes]]

Note that direct text editing does not trigger the cookies recalculation. This only happens only after using one of the commands like ~M-x org-toggle-checkbox~ or ~M-x org-update-statistics-cookies~ (specifically to do the recalculation).

* Tables

Table is added with ~|~, like this:

| Table Heading    | Table Heading  |
|------------------+----------------|
| Table cell       | Table cell     |
| Table cell two   | Table cell two |
| Aligned with TAB |                |
|                  |                |

Table is reformatted with ~TAB~ when cursor is inside the table.

* Markup

Markup is different from Markdown, but similar by nature:
- *Bold* (~*Bold*~)
- /italic/ (~/italic/~)
- _underline_ (~_underline_~)
- =verbatim= (~=verbatim=~)
- ~code~ (~~code~~)
- +strike-through+ (~+strike-through+~)

Markup can be combined: _*/combination/*_ (~_*/combination/*_~)
+ ~_*/combination/*_~ did not work? does not look like italic... the guide says it can be combined in any order

~code~ (~~code~~) and =verbatim= (~=verbatim=~) needs to be the inner-most markup.

More information: [[https://orgmode.org/worg/org-syntax.html#Emphasis_Markers][Emphasis Markers]]

* Editing raw markup

Org mode renders the markup, so, for example, after you add a link, it is hard to edit the URL.

Switching to ~M-x fundamental-mode~ shows everything as plain text.

* Blocks and Code Blocks

#+begin_example
block example
#+end_example

#+BEGIN_SRC emacs-lisp
(message "Hello World")
#+END_SRC

Code blocks can be executed. The emacs lisp is working by default and more languages can be added like this (a snippet from the emacs config):

#+BEGIN_SRC emacs-lisp
;; use python3
(setq org-babel-python-command "python3")
;; Enable python and bash support in org-babel,
;; so that we can run code blocks in org-mode.
(org-babel-do-load-languages
 'org-babel-load-languages
 '((python . t)
   (shell . t)))
#+END_SRC

Execute the code block with ~M-x org-babel-execute-src-block~, the output goes into the following ~#+RESULTS~ block:

#+BEGIN_SRC bash
echo "Hello World (bash)"
#+END_SRC

#+RESULTS:
: Hello World (bash)

#+BEGIN_SRC python
return "Hello World (python)"
#+END_SRC

#+RESULTS:
: Hello World (python)

We have access to the outside world too, for example, get the list of `*.el` files in the current folder, calculate file sizes and print as a table:

#+BEGIN_SRC python
    from pathlib import Path
    elFiles = []
    for el_file in Path("./").glob("*.el"):
        elFiles.append([
            el_file.name,
            "{:4.1f} KiB".format(el_file.stat().st_size / 1000)])
    return elFiles
#+END_SRC

| init.el        | 43.4 KiB |

* Coming home to Emacs (this should be an essay)
I think [[https://stevelosh.com/blog/2010/09/coming-home-to-vim/][Steve Losh described perfectly]] how and why Vim can be your home.

First and foremost, the vim editing model with normal and insert that let you *navigate* and *edit the text* the text [[https://pragprog.com/titles/dnvim2/practical-vim-second-edition/][with the speed of thought]] are much worth understanding and mastering.

Second, the idea that "everything is a text" is very powerful: this works in the Unix shell, with commands reading text and producing text and it works in editors like Vim where everything you see is the text that you can copy and modify. For example, if you run an SQL client inside Vim there is never a problem of "exporting" the query result which you may need to do in a traditional GUI SQL client. In Vim it is just text that you can copy and paste elsewhere.

The "everything is a text" is heavily supported by splits in editors like vim and emacs: at any given point I can split my screen into several panes and:
+ See parts of the same file (for example, the function definition and the calling code)
+ See related files side-by-side (for example, code and tests)
+ Open tools the same way as files: file manager, SQL client, terminal, project search, git client, ...
  + Every tool has the same UX: scroll, navigate, search work the same way.
  + I can copy the output and paste/edit it (for example, copy commands I and in terminal along with the output and paste into the documentation)
+ All this significantly reduces the context switch and navigation effort that is common for GUI apps.
  + For example: start IDE, start SQL client, run some commands in SQL client, export the output to the file, open the file in the spreadsheet app, copy, paste in the documentation file I am working on in the IDE, etc.
  + The above can be done in the same interface that you can easily tailor for your current task by creating splits for your documentation file and SQL client, running SQL, copying and pasting the result. All without ever switching from one app to another. All while being able to see both tools at the same time without arranging GUI windows.
  + Side-note: people coming from IDEs often try to reproduce the UI/UX in editors like Vim and Emacs which may lead to loosing the advantage. See [[http://vimcasts.org/blog/2013/01/oil-and-vinegar-split-windows-and-project-drawer/][Drew Neil's Oil and Vinegar]] where he explains how having a file manager in a regular text buffer creates a better flow than having it in a dedicated "project drawer" in the sidebar.

Third, as a programmable editor, Vim gives you much freedom and lots of tools made by others that you can adopt, modify and improve.

But here comes a shortcut: if you ever tried writing vimscript, it does not feel very nice. There are [[https://github.com/tpope][people]] who master it and create extremely useful tools. The neovim's move to Lua is a big improvement and it sparked a revolution of even more complex tools and tools that reinvent the vim UI, look and feel ([[https://github.com/nvim-mini/mini.nvim][mini.nvim]], [[https://github.com/nvim-telescope/telescope.nvim][telescope]]).

This is where emacs comes in place: it is not just a programmable editor with a scripting language added as a way to extend it. It is a programming language (Emacs Lisp) environment at its core. The language itself (lisp) is unique in its simplicity which gives it an incredible flexibility (see [[https://paulgraham.com/rootsoflisp.html][roots of lisp by paul graham]], [[https://wiki.eecs.yorku.ca/course_archive/2014-15/W/6339/_media/jmc.pdf][pdf]], [[https://en.wikipedia.org/wiki/Structure_and_Interpretation_of_Computer_Programs][Structure and Interpretation of Computer Programs]]).
